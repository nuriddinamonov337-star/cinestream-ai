## Project: CineStream AI (Telegram movie bot)

Stack: TypeScript + React 19 + TanStack Router/Start + Vite + Nitro + Supabase.
Target deploy: Railway (Nitro `node-server` preset).

### Commands
- Build: `npm run build` (outputs `.output/server/index.mjs`, Nitro node-server)
- Typecheck: `npx tsc --noEmit`
- Tests: `npm run test` (vitest run, `src/lib/telegram/api.test.ts`)
- Lint: `npx eslint . --fix` (note: ~20 pre-existing `any` warnings in original codebase)

### Architecture notes
- Telegram bot logic lives in `src/lib/telegram/`:
  - `api.ts` — direct Telegram Bot API wrapper (`tg`, `tgSafe`, `inlineKeyboard`).
  - `handlers.ts` — webhook handler: `/start`, forced-subscription check, movie-code search, admin panel, FSM states, reels.
  - `db.ts` — Supabase service-role client + `getSetting`/`setSetting`/session helpers.
  - `reels.ts` — Reels job lifecycle (`requestReels`, `completeReelsJob`, `getReelsWebhookUrl`).
  - `webhook-setup.ts`, `webhook-n8n.ts` — webhook config + n8n integration.
- Webhook endpoint: `src/routes/api/public/telegram/webhook.ts` (validates `X-Telegram-Bot-Api-Secret-Token`).
- Reels callback endpoint: `src/routes/api/public/reels/callback.ts` (validates `X-Reels-Secret`).
- Health endpoint: `src/routes/api/health.ts`.
- Python reels microservice: `reels-service/` (FastAPI, `app/main.py` — `process_job` is a stub).
- Supabase types are auto-generated in `src/integrations/supabase/types.ts` (regenerated by `vite build`).

### FSM convention
- `admin_sessions` table stores multi-step dialog state via `getSession`/`setSession`/`clearSession`.
- Admin-only states (add_movie, n8n, reels_url) are handled in `handleAdminFSM` (gated by `isAdminUser` at the caller).
- User-facing states (awaiting_receipt, reels:link) are handled in the general text-message handler, OUTSIDE the admin gate.

### Migration status (Lovable → Railway)
- Lovable gateway dependency removed; bot calls `api.telegram.org` directly.
- `.env` removed from git tracking (local preserved); secrets live in Railway Variables.
- See `.agents_tmp/PLAN.md` for the full migration plan and per-bosqich status.

### Gotchas
- Do NOT push to remote or open PRs unless explicitly asked.
- The `routeTree.gen.ts` file is auto-generated — it regenerates during `vite build`; new route files must be picked up by a build before `tsc` passes.
- Keeping a `/tmp/my_handlers.ts` snapshot during risky edits is useful; the snapshot preserves the complete good state for restore.
